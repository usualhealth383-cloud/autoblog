# 바코드 등록 · 공공 투약 이력 불러오기 — 조사 메모 (11-17 밤 · 코드 바꾸지 않음)

## ③ 바코드 등록 — 약 상자 바코드로 제품 찾기
- **약 상자 바코드 = 의약품 표준코드(KD코드) 13자리**: 국가 880 + 제조·수입업체 4자리 + 품목 5자리 + 검증 1자리(GS1 체계). — [심평원 약가마스터 설명](https://www.data.go.kr/data/15067462/fileData.do)
- **우리가 이미 받는 식약처 허가 목록 응답에는 바코드(13자리)가 없다** — 실측(fields-probe.json): `EDI_CODE`(보험 제품코드 9자리, 일반약은 비어 있음)·`PRDLST_STDR_CODE`(품목기준코드)만 있음.
- **이을 길**: 심평원 「약가마스터_의약품표준코드」(data.go.kr 15067462, 파일 · 최신 20260831판) — 표준코드(13자리) ↔ 제품코드(보험) 매핑 → 허가 목록의 `EDI_CODE` 로 품목(ITEM_SEQ)까지 이어짐.
  - 한계: «약제급여목록에 고시된 제품코드» 누적이라 **보험 약(처방약 대부분)만** — 비급여 일반약(감기약·진통제 상자)은 빠질 가능성이 큼 [확인 필요]. 일반약 바코드 자료(대한상공회의소 「바코드연계제품정보」)는 유료·2018년 뒤 갱신 중단이라 쓰지 않음.
  - 참고 자료: [ATC코드 매핑](https://www.data.go.kr/data/15118958/fileData.do) · [표준코드 부여 공고](https://www.khidi.or.kr/board/view?menuId=MENU01499&linkId=48937555)
- **자료 신청(현욱님께)**: 「건강보험심사평가원_약가마스터_의약품표준코드」 — 파일은 로그인 없이 내려받기 가능하다고 나오지만, GitHub 작업에서 자동으로 받으려면 같은 자료의 «파일데이터 API»(있으면) 활용신청이 필요 [확인 필요]. 받으면: 바코드 → 처방약 품목 연결 표를 짓고, 일반약은 지금처럼 사진·이름으로.
- 앱 쪽 일: 카메라 바코드 읽기(웹은 BarcodeDetector 지원 브라우저만, 앱은 플러그인) — 표가 오면 시안.

## ④ 공공 투약 이력 불러오기 — 이용자가 받은 파일을 넣는 방식
- **심평원 「내가 먹는 약! 한눈에」**: 최근 1년 투약 내역·알레르기·부작용, 14세 미만 자녀 조회 — 파일로 내려받는 기능은 확인 못 함. — [데일리팜](https://dailypharm.com/user/news/59005)
- **보건복지부 「나의건강기록」 앱**: 심평원 투약 이력(최근 1년)·건보 진료·검진·예방접종을 한곳에서 — **«원하는 정보만 골라 파일로 저장하거나 원하는 곳으로 전송»** 가능하다고 소개됨 → 이 파일을 약지도에 넣는 방식이 가장 현실적. 파일 형식(PDF·JSON 등)은 [확인 필요] — 실제 앱에서 한 번 내려받아 봐야 함. — [정책브리핑](https://www.korea.kr/news/policyNewsView.do?newsId=148922265)
- **마이헬스웨이(의료 마이데이터)**: 민간 앱이 직접 연계하는 길 — 참여 조건·심사는 공식 공고 확인 필요, 서버·인증 필요(지금 단계 아님). — [데일리팜](https://dailypharm.com/user/news/54057)
- 제안: ① 현욱님(또는 직원)이 「나의건강기록」에서 본인 투약 이력 파일을 한 번 내려받아 형식 확인 → ② 형식이 표(제품명·성분·일수)면 «파일 넣기 → 제품명을 우리 약 목록에 맞춰 약통에 담기» 시안(기기 안에서만 읽고 서버에 올리지 않음).

## 결정이 필요한 것
- 바코드: 표준코드 파일데이터 API 활용신청 여부.
- 투약 이력: 「나의건강기록」 파일 한 건(가린 것) 받아 형식 확인.
