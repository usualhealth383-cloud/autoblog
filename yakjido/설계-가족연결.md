# 설계 — 가족 연결 「부모님께 약 보내기」 (2026-10-01, 현욱님 지시)

> 「자식이 클릭해서 이 약을 구입하라고 부모님께 보내드리면 부모님이 인근 약국에 가서 자식이 고른 약을 구입할 수 있게」
> 「개인정보 동의 구하고 서버를 운영하자 — Supabase」

## 흐름
1. **자녀**: 증상 화면·약 화면에서 약을 고름 → 「부모님께 보내기」 → (처음 한 번) 동의 화면 → 받는 분 호칭(엄마·아빠 등, 선택)과 한 줄 메모(선택) → 카카오톡·문자로 링크 공유.
2. **부모님**: 링크를 누르면 앱 설치 없이 열리는 **큰 글씨 화면** — 약 사진·이름·성분·「약사님께 이 화면을 보여 주세요」 + 「가까운 문 연 약국 찾기」 + 「약사에게 앓는 병·드시는 약을 꼭 말씀하세요」.
3. 부모님이 「샀어요」를 누르면 자녀 앱에 표시(선택 기능, 2단계).

## 서버에 두는 것 — 최소한만
| 항목 | 저장 | 이유 |
|---|---|---|
| 약 목록(약지도 약 id·제품명) | ○ | 화면을 그리는 데 필요 |
| 호칭·메모 | ○(선택, 100자) | 부모님이 누가 보냈는지 알게 |
| 이름·전화번호·생년월일·주소 | **✕** | 받지 않음 |
| 위치 | **✕** | 약국 찾기는 부모님 휴대폰에서 e-gen 으로 바로 |
| 기기 식별자·광고 ID | **✕** | |
| 만료 | **7일 뒤 자동 삭제** | 오래 남길 이유가 없음 |

- 링크 주소 = 추측 불가능한 무작위 코드(128비트). 코드를 아는 사람만 열람.
- 약 목록 + 메모는 건강에 관한 정보로 볼 수 있어 **「민감정보 처리 별도 동의」**(개인정보보호법 제23조)를 받는다. 만 14세 미만은 보내기 기능을 쓰지 않도록(법정대리인 동의 필요).

## Supabase 구성
- 리전: **서울(ap-northeast-2)**. 「새 테이블 자동 공개」 끔, 「자동 RLS」 켬.
- 테이블 `shares(id uuid 기본, code text unique, items jsonb, label text, note text, created_at, expires_at)` — RLS 켜고 **anon 은 SELECT/INSERT 직접 금지**.
- 쓰기·읽기는 **Edge Function 2개**로만: `share-create`(입력 검증·크기 제한·초당 요청 제한, code 생성) / `share-get`(code 로 1건, 만료면 410).
- 매일 만료 행 삭제(`pg_cron`).
- 앱에는 **공개 키(anon)만** 들어가고, 서비스 키는 서버(함수)에만. 키는 저장소에 적지 않고 GitHub Secrets / Supabase 설정에.

## 비용
- Supabase 무료 플랜: 프로젝트 2개까지 0원(지금 조직 하나에 1개 사용 중). **무료 프로젝트는 1주일 동안 요청이 없으면 일시 정지**되어, 실제 출시 땐 Pro(월 25달러)를 권장 — 출시 전 다시 여쭙기.
- Edge Function 호출·DB 용량은 이 기능 규모(문자 몇 줄)로는 무료 한도 안.

## 앱에 바꿔야 할 것
- 「개인정보처리방침」에 이 기능 한 절(수집 항목·목적·보관 7일·위탁: Supabase Inc., 국외 이전 여부 — 서울 리전이면 저장은 국내).
- 첫 실행 동의 벽은 만들지 않음(소파 원칙) — **보내기를 처음 누를 때만** 동의.
- 기존 원칙 「내 기록은 휴대폰에만」은 그대로: 약통·복용 기록·혈압은 서버로 가지 않음. 서버로 가는 것은 **자녀가 보내기를 누른 그 목록 하나**뿐.
