# 약지도 — 구글 플레이 출시 준비 (2026-09-29)

결론: **앱 자체는 준비됨. 막힌 것은 사업자명 하나**입니다 — 건강 앱은 조직(사업자) 계정으로만 올릴 수 있어서, 사업자등록 → D-U-N-S 번호 → 조직 계정 순서입니다.

## 1. 현욱님이 정하실 것

### 개발자 계정 — **조직(사업자) 계정으로 해야 합니다** (선택 사항이 아님)
구글은 **건강·의료 앱은 조직 계정으로만** 등록하게 합니다. 약지도는 복약 알림·약 정보 앱이라 여기에 해당합니다.

| | 개인 계정 | 조직(사업자) 계정 |
|---|---|---|
| 건강·의료 앱 | **올릴 수 없음** | 올릴 수 있음 |
| 필요한 것 | 신분증 | **사업자등록 + D-U-N-S 번호**(무료 기업 식별번호, 발급에 며칠~몇 주 [확인 필요]) |
| 출시 전 시험 | 12명 × 14일 비공개 시험 필수 | 면제 |
| 스토어에 보이는 이름 | 개인 이름 | 사업자명 |
| 등록비 | 25달러 1회 | 25달러 1회 |

→ 그래서 **사업자명**(71번에서 「다음에」로 미룬 것)이 스토어 출시의 첫 관문입니다. 개인사업자 등록증으로도 D-U-N-S 를 받을 수 있습니다 [확인 필요: 국내 발급 절차 — NICE평가정보가 대행].

| # | 항목 | 왜 필요한가 | 제안 |
|---|---|---|---|
| 1 | **사업자명·사업자등록** | 조직 계정·D-U-N-S·개인정보처리방침에 들어감 | 기존 사업자가 있으면 그것으로 |
| 2 | **D-U-N-S 번호** | 조직 계정 필수 | 사업자등록 뒤 신청 |
| 3 | **스토어용 서명 키** | 업데이트마다 같은 키가 필요, 잃으면 앱을 새로 올려야 함 | README 의 `keytool` 한 줄로 만들고 GitHub Secrets 4칸에 넣기 — 제가 대신 만들지 않습니다(키를 파일·대화에 남기지 않기 위해) |
| 4 | **스토어 설명의 면책 문구** | 구글 정책: 의료기기가 아닌 건강 앱은 「의료기기가 아니며 진단·치료하지 않는다, 전문가와 상의하라」를 설명에 넣어야 함 | 아래 6번 초안 |

## 2. 구글 플레이 정책 대조

| 정책 | 약지도 상태 |
|---|---|
| 건강 앱 신고서(Health apps declaration) — 모든 앱 필수 | 해당 항목: **복약 알림·약 관리**, 건강 정보 제공. 의료기기 아님으로 신고 [확인 필요: 국내 식약처 판단 — 일반 건강관리(웰니스) 범주로 보는 근거 정리 필요] |
| 정확한 알람 권한 | `SCHEDULE_EXACT_ALARM`(사용자가 켜는 방식)만 씀. 자동 허용되는 `USE_EXACT_ALARM` 은 알람시계·달력 앱 전용이라 **쓰지 않음** |
| 알림 권한(안드로이드 13+) | 첫 실행에 묻지 않고 「켜기」를 누를 때 물음 |
| 위치 | **대략 위치만**(날씨 카드 「내 위치」, 선택). 정밀 위치 권한 없음 |
| 카메라 | 권한 선언 없음 — 휴대폰 기본 카메라 앱으로 찍어 넘겨받음. 사진은 기기 안에서 글자를 읽고 서버로 보내지 않음 |
| 목표 SDK | 36 (현행 요구 충족) |
| 데이터 보안 양식 | 아래 3번 |

## 3. 데이터 보안(Data safety) 양식 초안

| 데이터 | 수집(기기 밖으로 나감)? | 설명 |
|---|---|---|
| 먹는 약·복용 기록·몸 상태·불편했던 약 | **아니요** | 기기에만 저장. 서버로 보내는 코드 없음 |
| 대략 위치 | 예 — **일시적 처리, 저장 안 함** | 「내 위치」를 고른 경우에만, 소수 첫째 자리(약 10 km)로 줄여 날씨 서비스(Open-Meteo)에 보냄 |
| 사진 | 아니요 | 기기 안에서 글자 읽기 |
| 기기 식별자·광고 ID | 아니요 | 광고·분석 도구 없음 |

※ 71번(사용자 기록 서버 수집)이 들어가면 이 표가 바뀝니다 — 그때 다시 씁니다.

## 4. 개인정보처리방침

> 2026-09-29 현욱님 「지금 올리기」 → `docs/yakjido/privacy.html` 로 만들었고 앱의 「이 앱에 대해」에 링크를 달았습니다.
> 공개 주소는 GitHub Pages 가 `main` 브랜치만 내보내므로, **약지도를 `main` 에 합친 뒤에** 생깁니다: `https://usualhealth383-cloud.github.io/autoblog/yakjido/privacy.html`

**약지도 개인정보처리방침**
시행일: [확인 필요] · 처리 주체: [사업자명 확인 필요] · 문의: [연락처 확인 필요]

1. **모으는 정보 — 없습니다.** 약지도에 적으신 약·복용 기록·몸 상태는 **이 휴대폰 안에만** 저장되며, 저희 서버로 보내지 않습니다. 저희는 그 내용을 볼 수 없습니다.
2. **위치** — 날씨 카드에서 「내 위치」를 고르신 경우에만 대략 위치(약 10 km 단위)를 날씨 서비스(Open-Meteo)에 보내 그날 날씨를 받아 옵니다. 저장하지 않습니다. 도시를 직접 고르시면 위치를 쓰지 않습니다.
3. **사진** — 약 사진은 휴대폰 안에서 글자를 읽는 데만 쓰고, 보내거나 저장하지 않습니다.
4. **알림** — 복용 알림은 휴대폰 자체 알람으로 울립니다. 알림 내용(약 이름)은 휴대폰 밖으로 나가지 않습니다.
5. **지우기** — 앱을 지우거나 「내 정보 → 휴대폰을 바꾸실 때 → 이 휴대폰의 기록 모두 지우기」를 누르시면 모두 사라집니다. 저희 쪽에 남는 것은 없습니다.
6. **만 14세 미만** — 보호자와 함께 쓰시길 권합니다.
7. 이 방침이 바뀌면 앱과 이 페이지에서 알려 드립니다.

## 5. 스토어 설명 면책 문구 초안
> 약지도는 의료기기가 아니며, 질병을 진단·치료·예방하지 않습니다. 약의 선택과 복용은 약사·의사와 상의하세요. 응급 증상이 있으면 119 또는 가까운 응급실로 가세요.

## 6. 벤치마크
메디세이프는 알림·「먹었어요」·다시 알림·재고 알림·보호자 알림까지 합니다.
약지도는 보호자 자동 알림을 뺀 나머지를 모두 갖췄고, **일반약 병용 경고·어르신 주의·소아 체중 용량**은 메디세이프에 없는 차별점입니다.
또 **기록을 서버로 보내지 않는다**는 것 자체가 스토어 설명에 쓸 수 있는 강점입니다(71번 결정 전까지).
