### D1. 만 14세 미만 가입 구조 (#1·#2)

**근거** — 법 제22조의2 ①: 아동 개인정보를 동의로 처리하려면 법정대리인 동의를 받고 확인해야 한다. ② + 시행령 제17조의2 ②: 동의 전에 아동에게서 받아도 되는 것은 **법정대리인의 성명·연락처뿐**. 지금은 아동의 이메일·비밀번호·이름이 동의 전에 정식 계정으로 서버에 들어간다(7일 안 동의 없으면 삭제). 10-13에 학습 기록·이야기·결제·알림·QR 신청은 동의 뒤로 막았지만(서버 `consent_ok()`), 계정 자체는 시행령이 정한 범위를 넘는다. 우리 수강생 중 만 14세 미만은 **중등부반(현 중2)** 정도 — 고1 대상 앱이라 수가 적다.

**제안 — A2안: 학원 서면 동의 → 가입 코드(지금 출시에 맞춤)**
- 학원 등록 때 이미 받는 서류에 '앱 이용 동의'(시행령 제17조의2 ①4호 — 서면 서명)를 넣고, 원장이 원장 화면에서 **1회용 가입 코드**(14일 유효)를 만든다. 서버에는 코드·만든 시각·보호자 성함만 남는다.
- 만 14세 미만은 앱에서 그 코드를 넣어야 가입이 된다(`on_signup` 이 코드를 확인하고 바로 `guardian_ok`). 코드가 없으면 가입하지 않고 둘러보기(최근 7일치)만.
- 동의 전에는 아동 정보가 서버에 하나도 없다 — 법 문언과 가장 가깝고, 학원의 실제 등록 흐름과 같다.
- 공사: 서버 S~M(가입 코드 표·발급 함수·`on_signup` 검사·`purge_old`·시험) 0.5일 · 앱 S(가입 4단계 코드 칸·원장 화면 코드 만들기) 0.5일 · 시험·문서 0.5일 → **약 1.5일**. 웹 동의 페이지(`consent.html`)는 기존 동의 대기 계정 처리용으로만 남김.

**다른 안**
- **A1안: 동의 확인 전에는 정식 계정을 만들지 않는 웹 동의 구조**(학원 밖 아동도 받을 때). ① 아동 기기에 이메일·비밀번호·이름을 **기기 안에만** 둠 ② 서버 `consent_pending`(토큰·보호자 성함·연락처·시각)만 만들고 아동이 `sms:` 로 링크를 보냄 ③ 보호자가 동의 페이지에서 동의 표시(이때 자녀 이름은 보호자가 적음) ④ 원장이 등록 서류와 대조해 확인 문자(지금 규칙 그대로 — 시행령 제17조의2 ①1호) ⑤ 아동 기기가 토큰으로 상태를 확인해 '확인됨'이면 그때 가입(`on_signup` 이 토큰을 확인·소모) ⑥ 확인 안 된 대기는 7일, 확인됐는데 가입 안 한 것은 14일 뒤 삭제. 공사: 서버 M 1일 · 앱 M~L 1.5~2일(가입 흐름 갈래·기기 보관·대기 화면·로컬 모드) · e2e_consent 다시 쓰기 0.5일 → **약 3~4일**.
